# NewLife.MySql 需求文档

> 版本：v1.3 | 日期：2026-08-02
> 本文档描述 NewLife.MySql 的愿景、核心目标和功能方向。完成状态在[功能清单](功能清单.md)中追踪，详细设计在[架构设计](架构设计.md)中展开。

## 1. 背景与愿景

### 1.1 系统定位

**纯国产、零第三方依赖、高性能的 MySQL ADO.NET 驱动**，面向 XCode ORM 生态、ADO.NET 开发者与大数据批量场景，覆盖 MySQL 5.x ~ 9.0+ 及 OceanBase、TiDB、Doris 等兼容数据库。

| 工程 | 定位 | 目标用户 |
|------|------|---------|
| `NewLife.MySql` | 核心 ADO.NET 驱动 | XCode 开发者、ADO.NET 开发者、大数据开发者 |
| `NewLife.MySql.EntityFrameworkCore` | EF Core Provider（.NET 6+） | EF Core 开发者 |
| `NewLife.MySql.EntityFramework` | EF6 Provider | EF6 存量开发者 |

### 1.2 愿景

- **批量性能显著领先**：管道化批量 DML（`Pipeline` + 事务）实现批发批收，千级行 INSERT 加速比达 35×，万级行场景数百倍于逐行写入
- **零第三方依赖**：仅依赖 `NewLife.Core`，MIT 许可，信创环境自主可控
- **全框架覆盖**：`net45` ~ `net10` 全版本，MySQL 5.5 ~ 9.0+ 全系列
- **协议能力完整**：多认证、SSL/TLS、压缩、Binlog 订阅、Geometry、WebAuthn 等高级特性齐备

## 2. 核心目标

| 编号 | 目标 | 所属层级 | 一句话描述 |
|------|------|----------|------------|
| SYS | 系统基础 | 基础层 | 连接建立/认证/配置/连接池/健康检查与 DI 集成 |
| NET | 网络协议 | 基础层 | MySQL 协议核心、压缩传输与 Binlog 变更订阅 |
| SQL | 查询执行 | 核心层 | 标准查询接口、参数化、预编译、事务、存储过程与结果集消费 |
| BATCH | 批量操作 | 核心层 | 多通道批量 DML 与高性能批量导入 |
| META | 元数据与兼容 | 核心层 | Schema 元数据查询与多数据库兼容检测 |
| EF | 框架集成 | 扩展层 | XCode / EF Core / EF6 生态无缝集成 |

## 3. 功能需求

### 3.1 SYS — 系统基础

- **SYS-1 连接建立与握手**：MySQL Protocol V10 握手建连，连接打开/关闭/切换数据库全生命周期管理。
- **SYS-2 多认证方式**：支持 `mysql_native_password`、`caching_sha2_password`（含 RSA 公钥全量认证）、Auth Switch 认证切换。
- **SYS-3 WebAuthn 免密认证**：支持 MySQL 8.2+ `authentication_webauthn_client` 插件流程（FIDO2）。
- **SYS-4 连接字符串解析**：20+ 参数及别名解析（Server/Port/Database/UserID/Password/超时/池参数/压缩/管道/重试等）。
- **SYS-5 SSL/TLS 加密连接**：`SslMode` None/Preferred/Required，支持 TLS 1.2 / 1.3。
- **SYS-6 Unix Socket 连接**：通过连接字符串 `Socket` 参数走 Unix 域套接字（.NET Core 5.0+ Linux/macOS）。
- **SYS-7 连接池管理**：按连接字符串哈希分池，池大小/存活期/空闲回收可配置，服务器变量缓存。
- **SYS-8 连接健康检查**：借出/归还时按活跃/到龄/空闲规则判定复用、PING 验活或丢弃。
- **SYS-9 MySqlDataSource DI 集成**：.NET 7+ `DbDataSource` 抽象实现，支持 DI 容器注册。

### 3.2 NET — 网络协议

- **NET-1 MySQL 协议核心**：帧编解码、COM_QUERY/STMT_PREPARE/EXECUTE/INIT_DB、多结果集、断线重试（仅读语句）。
- **NET-2 压缩协议**：`UseCompression` 启用 zlib 压缩传输，发送/接收路径池化复用。
- **NET-3 Binlog 变更订阅**：订阅 MySQL binlog 事件流，支持库/表过滤、自动重连、断点续传。
- **NET-4 读缓冲与零分配优化**：`ReadBuffer` 缓冲复用、`OwnerPacket`/`ArrayPool` 内存管理，减少 GC 压力。

### 3.3 SQL — 查询执行

- **SQL-1 查询执行接口**：`ExecuteReader`/`ExecuteScalar`/`ExecuteNonQuery` 及全链路 `async/await` 真异步。
- **SQL-2 参数化查询**：`@参数名` 客户端替换，自动转义防注入，跳过字符串字面量，全类型支持。
- **SQL-3 预编译语句**：`Prepare()` 走 `COM_STMT_PREPARE` 二进制协议，`UseServerPrepare` 全局开关。
- **SQL-4 数据类型映射**：文本/二进制协议完整编解码，MySQL 类型 ↔ .NET 类型精确映射。
- **SQL-5 Geometry 空间类型**：`MySqlGeometry` 封装 WKB（OGC 标准），参数读写与 DataReader 映射。
- **SQL-6 事务支持**：四种隔离级别，Dispose 未提交自动回滚。
- **SQL-7 存储过程调用**：`CommandType.StoredProcedure`，IN/OUT 输出参数。
- **SQL-8 DataReader 增强**：多结果集遍历、`ReadModelsAsync<T>` 实体映射、BulkRead/ReadTableAsync 零拷贝。
- **SQL-9 DataAdapter 支持**：`MySqlDataAdapter` 填充 DataTable/DataSet。

### 3.4 BATCH — 批量操作

- **BATCH-1 字典参数集批量**：`ExecuteBatch` 接受字典参数集，自动 Prepare + Execute × N。
- **BATCH-2 数组绑定批量**：`ExecuteArrayBatch` Oracle 风格数组绑定。
- **BATCH-3 管道化执行**：`Pipeline=true` 批发批收，失败续读保持连接干净。
- **BATCH-4 MySqlBulkCopy 批量导入**：DataTable/IDataReader → 表，基于 Pipeline+预编译+事务，替代 LOAD DATA。
- **BATCH-5 DbBatch API**：.NET 6+ 标准 `DbBatch` 批量命令 API。

### 3.5 META — 元数据与兼容

- **META-1 Schema 基础查询**：Databases/Tables/Columns/Indexes/DataTypes/ReservedWords 等元数据。
- **META-2 Schema 扩展查询**：Procedures/Views/Triggers/ForeignKeys/Users 等扩展集合。
- **META-3 兼容数据库检测**：握手版本串自动识别 MySQL/OceanBase/TiDB/Doris/Aurora/CloudSQL/MariaDB。

### 3.6 EF — 框架集成

- **EF-1 XCode ORM 集成**：`MySqlClientFactory` 自动注册为 XCode 的 MySQL 驱动。
- **EF-2 EF Core Provider**：`UseMySql` 配置、类型映射、LINQ 翻译、迁移、AUTO_INCREMENT。
- **EF-3 EF6 Provider**：EF6 全套 Provider 服务（配置/迁移生成/历史上下文等）。

## 4. 🧊 暂缓清单

| 功能 | 暂缓理由 | 解冻前提 |
|------|----------|----------|
| 压缩协议 zstd 支持 | 源码仅实现 zlib，PackageTags 声明含 zstd | 明确 zstd 需求后补充实现 |
| MFA 多因子认证完整流程 | 仅实现 WebAuthn 协商标志，完整流程复杂 | 有明确 MFA 客户需求 |
| NativeAOT 兼容 | 当前体系依赖动态特性，ROI 低 | 主要用户群转向 NativeAOT |
| 负载均衡 / 故障转移 | 应由中间件或 XCode 层处理 | 驱动层职责范围扩大 |

## 5. 不做什么

- **LOAD DATA LOCAL INFILE**：安全风险高，`MySqlBulkCopy` 基于 Pipeline 替代。
- **OpenTelemetry 集成**：已有 `Tracer` 体系可替代，不引入 OTel 依赖。
- **`sha256_password` 认证**：已被 MySQL 8.0 废弃。
- **`ed25519` 认证**：MariaDB 专属，非目标场景。
- **压缩协议以外的协议层能力**：不实现超出 MySQL 官方协议范围的私有扩展。

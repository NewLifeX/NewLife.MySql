# 多语言本地化

> 基线：NewLife.Core 12 编译期词表｜运行时 11 种语言｜英文为源文与兜底

## 1. 语言分层

本库按 NuGet 下载量分层维护运行时词表：下载量较高的核心组件对齐 NewLife.Core 的 31 种语言，其余组件维护 11 种语言（与 README 读者一致）。缺失译文在运行时自动回退英文，新增语言不需要改代码。

词表文件（10 个，另有英文源文兜底）：

- zh-Hans
- zh-Hant
- es
- de
- ja
- fr
- pt
- ru
- ko
- ar

## 2. 词表文件

- `NewLife.MySql/Locales`

- 文件名即 BCP 47 语言代码；英文是源文与兜底，**不需要** `en.yml`。
- 键为**英文原文**，必须与代码字符串逐字一致（含空格与标点）；占位符 `{0}` 与格式说明符 `{1:n0}` 必须与英文一致。
- 词表由 NewLife.Core 包内的源生成器在编译期读取并生成压缩语言表，NativeAOT 下同样可用。

## 3. 新增一条消息

1. 代码中写英文源文：异常与同步消息用 `L.T`，例如 `throw new InvalidOperationException(L.T("Session {0} is closed.", sessionId));`；日志直接写英文模板（`Logger.Format` 自动翻译）。
2. 在全部语言文件的同一位置补齐该键；遗漏只回退英文，不会编译失败。
3. 运行校验脚本确认键集合、占位符与格式说明符一致。

### 3.1 带前缀写日志

动态前缀（实例名、会话编号等）不要拼进格式化字符串，否则整串无法命中词表。先翻译消息再拼接前缀：

```csharp
Log?.InfoPrefixed("[Session] ", "Received {0} bytes", count);
Log?.ErrorPrefixed("[Session] ", "Read error: {0}", ex.Message);
Log?.WritePrefixed(LogLevel.Warn, "[Session] ", "Queue is full: {0}", length);
```

`BinlogClient` 与 `MySqlBulkCopy` 均已提供 `LogPrefix` 属性，默认分别为 `[Binlog] ` 与 `[BulkCopy] `，`WriteLog` 内部走 `InfoPrefixed`。静态前缀可以直接写进源文并作为键的一部分。

## 4. 校验

```powershell
pwsh -File check-locales.ps1 -LocaleDir NewLife.MySql/Locales -Baseline zh-Hans.yml -SourceDir NewLife.MySql
```

CI 的 localization job 会遍历全部 `Locales` 目录并执行同一脚本。

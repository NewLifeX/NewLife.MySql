# NewLife.MySql 性能测试报告

> **测试日期**：2026-11-22
> **对比驱动**：MySql.Data 26.10.0、MySqlConnector 3.0.0
> **环境**：Windows 10 / i9-10900K / MySQL 8.0.39 本机 / .NET 10 Release / TCP 无 SSL
> **方法**：预热 1 轮 + 测量 3 轮取中位数；逐行点查另做交替测量消除顺序偏差

---

## 结论

**批量 DML 领先 26%~41%，批量读取与实体映射领先 3%~33%，逐行点查与 MySqlConnector 持平，明显快于 MySql.Data。**

## 大方向对比（10,000 行，ms，越小越好）

| 方向 | NewLife | MySql.Data | MySqlConnector | 结论 |
|------|------:|------:|------:|------|
| 批量 INSERT（事务+管道） | **813.65** | 1,089.42 | 1,135.07 | 领先 26%~34% |
| 批量 UPDATE（事务+管道） | **856.47** | 1,151.05 | 1,196.44 | 领先 26%~34% |
| 批量 DELETE（事务+管道） | **816.03** | 1,090.58 | 1,125.95 | 领先 26%~34% |
| 批量读取（BulkRead） | **6.61** | 9.11 | 6.98 | 领先 5% |
| DbTable 填充 | **6.67** | 22.34 | 6.95 | 领先 4%，对 Official 3.35× |
| 实体映射（ReadModels） | **6.72** | 24.38 | 10.01 | 领先 33%，对 Official 3.63× |
| 逐行点查 | 1,181 | 1,374 | **1,141** | 与 Connector 持平（差 3.5%），对 Official 快 16% |

1,000 行结论一致：批量 INSERT **93.59ms** vs 132.16 / 141.71；UPDATE **96.16ms** vs 121.33 / 124.59；DELETE **87.51ms** vs 112.20 / 118.33。

逐行点查交替测量：NL 116.8~119.1µs、Connector 109.9~118.4µs，差距 0~6%，属同一水平线；NL 中位/尾延迟通常更稳。

> 无事务逐行写入受本机 fsync 主导（1.3~15ms/行），三驱动差异 <5%，不作为驱动优劣依据。

## 本次优化

| 优化 | 效果 |
|------|------|
| 同步 I/O 快速路径（阻塞读写、无取消令牌/线程池续体） | 单命令省约 40µs |
| 列元数据缓存（SQL + 报文哈希校验） | 跳过字段名解码，分配 -1.3KB/命令 |
| 连接洁净标记（完整消费后跳过 socket 探活） | 省 2 次系统调用/命令 |
| 小包 scratch 缓冲 + 查询报文直写池化缓冲 | 减少 ArrayPool/MemoryStream/byte[] 分配 |
| TCP NoDelay、参数名 Span 查找 | 小包请求-响应更稳定 |

优化前后：10,000 行逐行点查 **1,700ms → 1,181~1,200ms**；单命令分配 **5.9KB → 3.5KB**。

## 复现

```bash
dotnet run -c Release --project Benchmark -- --batch    # 三驱动批量 DML
dotnet run -c Release --project Benchmark -- --select   # 三驱动 SELECT
dotnet run -c Release --project Benchmark -- --driver   # 逐行 CRUD 全量
```

连接串通过 `MYSQL_CONNSTR` 配置，默认 `Server=127.0.0.1;Port=3306;Database=benchmark;User Id=root;Password=root;`。

# NewLife.MySql 性能测试报告

> **测试日期**：2026-11-22
> **对比驱动**：MySql.Data 26.10.0、MySqlConnector 3.0.0
> **环境**：Windows 10 / i9-10900K / MySQL 8.0.39 本机 / .NET 10 Release / TCP 无 SSL
> **方法**：预热 1 轮 + 测量 3 轮取中位数；逐行点查另做交替测量消除顺序偏差

---

## 对比口径

- **批量 DML**：NewLife 使用数组绑定 + 服务端预编译 + 管道化（`Pipeline=true`）并在事务内提交；MySql.Data / MySqlConnector 没有等价的数组绑定 API，表中数据为“事务内预编译命令逐行执行”。MySqlConnector 的 `MySqlBatch`、MySql.Data 的 `AllowBatch` 属于多语句合并路径，本项未纳入对比。
- **读取路径**：BulkRead 三驱动都用 `DbDataReader.Read()` 逐行读取；DbTable / ReadModels 中，NewLife 使用驱动内置的 `ReadTableAsync` / `ReadModelsAsync`，另外两个驱动通过同一个 NewLife `DbTable` 辅助类读取其 `DbDataReader`。
- **逐行点查**：相同 SQL 与参数，交替测量以抵消顺序偏差。
- 表中“低 X%”均指 `(竞品耗时 - NewLife 耗时) / 竞品耗时`。

## 结论

**10,000 行批量 DML 耗时比 MySql.Data / MySqlConnector 低 25%~28%；批量读取与实体映射较 MySqlConnector 低 4%~33%，较 MySql.Data 低 27%~72%；逐行点查与 MySqlConnector 处于同一水平（0~6%），比 MySql.Data 低约 14%。**

## 大方向对比（10,000 行，ms，越小越好）

| 方向 | NewLife | MySql.Data（预编译循环+事务） | MySqlConnector（预编译循环+事务） | 结论 |
|------|------:|------:|------:|------|
| 批量 INSERT（事务+管道） | **813.65** | 1,089.42 | 1,135.07 | 低 25%~28% |
| 批量 UPDATE（事务+管道） | **856.47** | 1,151.05 | 1,196.44 | 低 26%~28% |
| 批量 DELETE（事务+管道） | **816.03** | 1,090.58 | 1,125.95 | 低 25%~28% |
| 批量读取（BulkRead） | **6.61** | 9.11 | 6.98 | 较 Data 低 27%，较 Connector 低 5% |
| DbTable 填充 | **6.67** | 22.34 | 6.95 | 较 Data 低 70%，较 Connector 低 4% |
| 实体映射（ReadModels） | **6.72** | 24.38 | 10.01 | 较 Data 低 72%，较 Connector 低 33% |
| 逐行点查 | 1,181 | 1,374 | **1,141** | 较 Connector 慢 3.5%，较 Data 低 14% |

1,000 行结论一致：批量 INSERT **93.59ms** vs 132.16 / 141.71（低 29% / 34%）；UPDATE **96.16ms** vs 121.33 / 124.59（低 21% / 23%）；DELETE **87.51ms** vs 112.20 / 118.33（低 22% / 26%）。

逐行点查交替测量：NL 116.8~119.1µs、Connector 109.9~118.4µs，差距 0~6%，属同一水平线；NL 中位/尾延迟通常更稳。

> 无事务逐行写入受本机 fsync 主导（1.3~15ms/行），三驱动差异 <5%，不作为驱动优劣依据。

## 本次优化

| 优化 | 效果 |
|------|------|
| 同步 I/O 快速路径（阻塞读写、无取消令牌/线程池续体） | 单命令省约 40µs |
| 列元数据缓存（SQL + 报文哈希校验） | 跳过字段名解码，分配 -1.3KB/命令 |
| 连接洁净标记（完整消费后跳过 socket 探活） | 省 2 次系统调用/命令 |
| 小包 scratch 缓冲 + 查询报文直写池化缓冲 | 减少 ArrayPool/MemoryStream/byte[] 分配 |
| TCP NoDelay、参数名 Span 查找 | 小包请求-响应更稳定 |

优化前后：10,000 行逐行点查 **1,700ms → 1,181~1,200ms**；单命令分配 **5.9KB → 3.5KB**。

## 复现

```bash
dotnet run -c Release --project Benchmark -- --batch    # 三驱动批量 DML
dotnet run -c Release --project Benchmark -- --select   # 三驱动 SELECT
dotnet run -c Release --project Benchmark -- --driver   # 逐行 CRUD 全量
```

连接串通过 `MYSQL_CONNSTR` 配置，默认 `Server=127.0.0.1;Port=3306;Database=benchmark;User Id=root;Password=root;`。

# NewLife.MySql 代码审计报告

> 审计范围：发布到 NuGet 的三个项目（`NewLife.MySql` 主驱动、`NewLife.MySql.EntityFramework`、`NewLife.MySql.EntityFrameworkCore`）
> 审计时间：2026-08-01
> 基线：全量编译 0 错误；UnitTest 758 通过、EFCore 79×2 通过、EF6 135 通过

---

## 1. 结论摘要

整体代码质量较高：协议解析零分配（`MySqlFieldCodec`）、管道化批量（`ExecutePipelineCoreAsync` 读写并发防死锁）、连接池探活（`ConnectionHealth` 纯函数 + socket Poll）设计良好。确认 **3 个 P1 高风险缺陷、3 个 P2 缺陷、2 个 P3 卫生问题**，以及 **6 个性能优化点、3 个架构优化点**。

## 2. 问题矩阵

| 编号 | 严重度 | 类别 | 位置 | 问题描述 | 处置 |
|------|--------|------|------|----------|------|
| D1 | P1 | 正确性 | `MySqlPoolManager.CreatePool` / `MySqlConnection.ChangeDatabase` | 连接池持有创建者连接的可变 `MySqlConnectionStringBuilder` 引用（别名）；当**创建池的那个连接**调用 `ChangeDatabase`（已打开场景：Close → `Setting.Database=...` → Open）时篡改共享池配置，之后从该池新建的连接连到错误数据库。现有 `TestChangeDatabasePoolIsolation` 用不同连接实例切换未覆盖此场景 | 修复：`CreatePool` 克隆 Setting 快照 |
| D2 | P1 | API | `MySqlDataSource` | `public sealed` 类但构造函数为 `internal`，外部无法 `new MySqlDataSource(connStr)`，DI/EFCore 场景不可用；XML 注释承诺与实现矛盾；无测试 | 修复：提供 public 构造 + 测试 |
| D3 | P1 | 数据风险 | `MySqlCommand.ExecuteDbDataReaderAsync` 重试循环 | `RetryOnNetworkFailure` 默认 true，仅事务内跳过重试；事务外 INSERT/UPDATE 在"服务端已执行、响应丢失"时重连重试会**重复执行 DML** | 修复：仅读语句（SELECT/SHOW/DESC/EXPLAIN）重试，DML 不重试 |
| D4 | P2 | 兼容性 | `MySqlCommand.SerializeValue` | `dt.ToString("yyyy-MM-dd HH:mm:ss.ffffff")` 未指定 `InvariantCulture`，日期/时间分隔符随区域变化时生成非法 SQL 字面量 | 修复：改用 InvariantCulture + 单测 |
| D5 | P2 | API 契约 | `MySqlCommand.Cancel()` | ADO.NET 契约要求取消执行，当前空实现 | 修复：抛 `NotSupportedException` 明确说明 |
| D6 | P2 | 代码质量 | `SqlClient.GetColumnsAsync` | `if (rs2.IsEOF) { }` 空 if 死代码 | 修复：删除 |
| D7 | P3 | 卫生 | `MySqlCommand.ExecuteBatchAsync`/`ExecuteArrayBatchAsync` | `using var operationLease` 缩进异常 | 修复：对齐 |
| D8 | P3 | 卫生 | `MySqlFieldCodec.ReadTextValue` | 死注释 `//var reader2 = new SpanReader(span);` | 修复：删除 |

## 3. 性能优化点

| 编号 | 位置 | 问题 | 预期收益 | 处置 |
|------|------|------|----------|------|
| P1 | `MySqlDataReader.ReadModelsAsync<T>` | 每行每列 `model.SetValue`（反射）+ `val.ChangeType` | 大结果集显著提速，消除每行反射 | 预编译 setter 委托缓存 |
| P2 | `SqlClient.NextBinaryRowAsync` | `reader.ReadBytes(nullBitmapLen)` 每行分配 null_bitmap 数组 | 消除每行 1 次分配 | 复用实例字段缓冲 |
| P3 | `MySqlDataReader.GetOrdinal` | `Array.FindIndex` 每次 O(n) + 委托分配 | 按名取列高频场景提速 | 缓存列名→序号字典 |
| P4 | `SqlClient.SendCompressedPacketAsync` | 每包 `new MemoryStream`+`DeflateStream`+`ToArray` | 压缩协议下大幅降分配 | 池化复用 |
| P5 | `SqlClient.BuildExecutePacket` | 管道化批量每行 `new OwnerPacket(8192)` | 批量场景降分配 | 评估复用/池化 |
| P6 | `MySqlBulkCopy.WriteToServerAsync` | 每行 `new Dictionary<String,Object?>`；`ExecuteBatchAsync` 每组 new `MySqlParameterCollection` | 批量导入降分配 | ✅ 已修复：统一值数组路径（`ExecuteBatchValuesAsync`），BulkCopy 每行直接构建 `Object?[]`，消除每行 Dictionary 与参数对象分配 |

## 4. 架构优化点

| 编号 | 位置 | 问题 | 处置 |
|------|------|------|------|
| A1 | `MySqlCommand.Dispose` | Dispose 中同步阻塞网络 IO（`UnprepareAsync().GetAwaiter().GetResult()`） | net6+ 通过 `DisposeAsync` 真正异步化 |
| A2 | `MySqlPool.OnGet` | 同步借出路径对 `NeedPing` 决策不补验活（仅异步 `GetAsync` 补 PING） | 统一验活逻辑（次要） |

## 5. 风险提示（记录不改）

- **重试语义变更（D3）**：仅读语句重试后，事务外 SELECT 在断线后重试可能读到旧快照，属可接受语义；DML 断线直接抛错，由上层决定重试。
- **同步包装异步（A1）**：ADO.NET 同步 API 必须包装异步实现，`ConfigureAwait(false)` 已在内部使用，死锁风险可控。

### 6.1 L2 压缩协议修复详情（重大缺陷）

修复前压缩协议（`UseCompression=true`）从未真正工作，本次排查出 **5 个叠加缺陷**：

| # | 缺陷 | 影响 | 修复 |
|---|------|------|------|
| 1 | 压缩包 payload 缺少 4 字节普通帧头 | 服务器无法解析 | `SendCompressedPacketAsync` 补普通帧头 |
| 2 | 用 `DeflateStream`（DEFLATE）压缩/解压，MySQL 用 zlib | 服务器拒绝 | `ZLibStream`（net6+）/ 手动 zlib（旧框架） |
| 3 | 行读取路径 `ReadRowPacketAsync` 未处理压缩 | 读压缩头错位 | 压缩模式下走统一压缩读取 |
| 4 | 普通包可跨压缩包分片，未处理 | 缓存边界越界 | 解压缓存 + 不完整包保留拼接（`_compressPending`） |
| 5 | 发送链式包 `GetSpan()` 只取链头单段 | 压缩遗漏 `Next` 链数据 | 合并整链后压缩 |

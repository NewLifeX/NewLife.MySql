# NewLife.MySql 代码审计报告

> 审计范围：发布到 NuGet 的三个项目（`NewLife.MySql` 主驱动、`NewLife.MySql.EntityFramework`、`NewLife.MySql.EntityFrameworkCore`）
> 审计时间：2026-08-01
> 基线：全量编译 0 错误；UnitTest 758 通过、EFCore 79×2 通过、EF6 135 通过

---

## 1. 结论摘要

整体代码质量较高：协议解析零分配（`MySqlFieldCodec`）、管道化批量（`ExecutePipelineCoreAsync` 读写并发防死锁）、连接池探活（`ConnectionHealth` 纯函数 + socket Poll）设计良好。确认 **3 个 P1 高风险缺陷、3 个 P2 缺陷、2 个 P3 卫生问题**，以及 **6 个性能优化点、3 个架构优化点**。

## 5. 风险提示（记录不改）

- **重试语义变更（D3）**：仅读语句重试后，事务外 SELECT 在断线后重试可能读到旧快照，属可接受语义；DML 断线直接抛错，由上层决定重试。
- **同步包装异步（A1）**：ADO.NET 同步 API 必须包装异步实现，`ConfigureAwait(false)` 已在内部使用，死锁风险可控。

### 6.1 L2 压缩协议修复详情（重大缺陷）

修复前压缩协议（`UseCompression=true`）从未真正工作，本次排查出 **5 个叠加缺陷**：

| # | 缺陷 | 影响 | 修复 |
|---|------|------|------|
| 1 | 压缩包 payload 缺少 4 字节普通帧头 | 服务器无法解析 | `SendCompressedPacketAsync` 补普通帧头 |
| 2 | 用 `DeflateStream`（DEFLATE）压缩/解压，MySQL 用 zlib | 服务器拒绝 | `ZLibStream`（net6+）/ 手动 zlib（旧框架） |
| 3 | 行读取路径 `ReadRowPacketAsync` 未处理压缩 | 读压缩头错位 | 压缩模式下走统一压缩读取 |
| 4 | 普通包可跨压缩包分片，未处理 | 缓存边界越界 | 解压缓存 + 不完整包保留拼接（`_compressPending`） |
| 5 | 发送链式包 `GetSpan()` 只取链头单段 | 压缩遗漏 `Next` 链数据 | 合并整链后压缩 |

## 7. 2026-11 安全加固（P0，已全部修复）

审计时间：2026-11-15。入口为「依赖升级 + 逻辑与安全隐患排查 + CI 失败治理」，本节记录安全侧结论与处置。

| 编号 | 严重度 | 位置 | 问题 | 处置 |
|------|--------|------|------|------|
| S1 | P0 | `SchemaProvider`（用户/Schema/表/存储过程/外键名与库名共 9 处） | `GetSchema` 的 restrictions 直接拼进引号字面量，上层把外部输入转手过来即注入 | 统一走 `MySqlCommand.EscapeString`；反引号标识符双写 |
| S2 | P0 | `MySqlCommand.EscapeString` / `Authentication.GetFlags` | 只做反斜杠转义，不识别 `NO_BACKSLASH_ESCAPES`；该模式下 `\'` 不闭合引号，单引号裸露 | 按 `sql_mode` 选择转义方式（双写单引号），`SqlClient.NoBackslashEscapes` 贯穿到参数替换与存储过程 IN/INOUT 参数 |
| S3 | P0 | `MySqlCommand.SerializeValue` | 兜底分支 `value.ToString()` 不加引号，`Char`/`TimeSpan`/`DateOnly` 等生成非法字面量；`Single`/`Double`/`Decimal` 缺 InvariantCulture | 补齐类型分支，未知类型统一加引号，数值统一 InvariantCulture |
| S4 | P0 | `SqlClient.StartSslAsync` | `SslStream` 证书回调恒返回 true，`SslMode=VerifyFull/VerifyCA` 形同虚设；服务端不支持 SSL 时静默降级明文 | `Verify*` 系列真校验链与主机名，失败抛 `AuthenticationException`；不支持 SSL 时同样报错 |
| S5 | P0 | `Authentication.GetFlags` | 无条件协商 `CLIENT_MULTI_STATEMENTS` | 改为默认关闭，新增连接串选项 `AllowMultiStatements`；`MySqlBatch` 关闭时逐条执行、多结果集读取报不支持；存储过程 OUT/INOUT 未开启时给明确提示 |
| S6 | P0 | `MySqlCommand.CreateCommandException` / `SqlClient.WritePacketLog` | 异常消息带替换成实际值的 SQL；`TracePackets` 打印认证响应与业务值 | 异常只保留命令文本 + 参数名；认证阶段跳过载荷 |

行为变更（需在发版说明中提示）：`AllowMultiStatements` 默认 false、`SslMode=Verify*` 会真实校验证书、未知类型参数改为带引号字面量。

## 8. 2026-11 第二批加固（P1/P2，已全部修复）

审计时间：2026-11-15。承第 7 节，继续处理 P1/P2 项。

| 编号 | 严重度 | 位置 | 问题 | 处置 |
|------|--------|------|------|------|
| R1 | P1 | `SqlClient.SendPacketAsync` / `ReadPacketAsync` | 单帧上限 0xFFFFFF，写入时只填低 3 字节，超 16MB 报文长度回绕，服务端按错长度解包 | 发送按 `MaxPayload` 切帧（整倍数时补 0 长度帧），接收合并续帧；17MB 往返用例 |
| R2 | P1 | `SqlClient.SendPacketAsync` | 写方向无超时，对端不收数据时命令与连接池一起挂死 | 按 `Timeout` 创建链接取消令牌，超时转 `TimeoutException` 并标记连接失效 |
| R3 | P1 | `MySqlCommand.ConvertToPositionalParameters` | 参数集合为空时把所有 `@name` 当占位符，`SET @x = 1` 被改写成 `SET ? = 1` | 新增 `positionalAt` 开关，仅值数组批量按位置绑定才替换裸 `@name` |
| R4 | P1 | `MySqlConnection.CloseCore` | 读取器未关闭就 Close 时连接仍归还连接池，残留结果集被下一个使用者读到 | 新增操作租约计数，仍有租约按脏连接销毁 |
| R5 | P2 | `MySqlConnectionStringBuilder.GetPoolKey` | 连接池以含明文口令的完整连接串为键，口令长期驻留字典 | 口令替换为 SHA256 摘要参与键，不同口令仍分属不同池 |
| R6 | P2 | `MySqlTransaction.Commit/Rollback` | 提交失败后 `_open` 仍为 true，调用方以为还能重试 | 失败即标记事务结束 |
| R7 | P2 | `Authentication` | 认证响应直接读 `rs.Data[0]/[1]`，空包越界；非 OK 包静默放过 | 长度校验 + 未知包按认证失败处理 |
| R8 | P2 | `Common/MySqlFieldCodec` | DATETIME/TIME 二进制读写按 `Millisecond` 计算，DATETIME(6) 亚毫秒被截断 | 改按 tick 计算微秒，读写往返一致 |
| R9 | P2 | `MySqlBatch` | 内层命令未继承批量的事务、超时、CommandBehavior | `CreateCommand` 统一下传 |
| R10 | P2 | `MySqlBulkCopy` | `RowsCopied` 事件的 `Abort` 标记不生效 | 事件后检查并停止继续读取 |
| R11 | P2 | `MySqlDataReader` | 未 Read 时取值为空引用；`GetBytes` 越界抛异常或返回错长度 | 统一经 `CurrentValues` 抛 `InvalidOperationException`；`GetBytes` 按 ADO.NET 契约裁剪 |

已知限制（本轮不修，留待有明确需求再做）：
- `HasRows` 仍以"最近一次 Read 到的行"判定，首次 Read 之前的空结果集返回 true。要做到 Read 前精确判定必须引入行缓冲预读，实测会让 `SchemaOnly`/`GetSchema` 系列全部回归，故保留现状。
- 连接池按连接串分池且无数量上限，与 `SqlConnection` 行为一致；连接串由调用方动态拼接时才可能累积。
- 读取器关闭时用 `CancellationToken.None` 清理协议流，属于有意的"尽力收尾"，不受调用方取消影响。
- 压缩连接下超过 16MB 的请求不支持（普通包与压缩包的长度字段都只有 3 字节），驱动直接报错提示关闭 `UseCompression`；接收方向已支持续帧拼接。
